# 共同原则

先写清读者要解决什么问题、交付什么以及允许怎样加工。任务很小时，一份明确的局部要求就够；不因工具齐全而给每项工作增加建库、风格研究或多角色流程。

原件承载证据，处理底本承载工作。保留原件，再生成可检索的文本、OCR 或句级编号副本。给底本登记来源 ID、位置类型和版本；底本变化后，旧位置不能直接沿用。脚本保证的是声明过的文本操作，不能证明 OCR 没有识别错字。

引用保存完整文字，摘要另列。归属、时间、判断与限制需要各自的依据。文字相同并不意味着说话人正确，也不意味着摘录支持稿件中的结论。事实、推断、虚构及待确认信息必须让读者和审读者分得清。

流程决定加工边界：纯删节只删除；保全式润色保留信息；真实经历不能编造。一部书可以组合流程，须在 brief 中写清各自作用的段落。

用实际文件验收。脚本报告只对所检查的输入和版本有效。内容审读需要指出覆盖范围、问题位置与依据；作者确认要有实际确认记录，执行者不能替作者宣布定稿。文件多、版本新、工具全通过均不自动代表作品完成。

通用方法只维护一份正式正文。单书记录哪些方法有效、在哪些条件下失败；可重复的方法按 [实践记录](../lessons/practice-notes.md) 回流。具体作者的习惯与价值判断不自动成为公共规则。
