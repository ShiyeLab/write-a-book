# 开始写作

先说明你手里有什么，以及这次希望完成什么。不需要先学会所有脚本或安装全部工具。能读取项目文件的 AI 先读 [AGENTS](../AGENTS.md)；聊天工具则由你提供执行说明、相应方法和当前材料。不能读取某种文件或联网时，明确当前可做什么、缺什么，继续处理不依赖该能力的工作。

## 已有资料

> 请先阅读本项目的 AGENTS.md 和使用说明。我想写一本关于【主题】、面向【读者】的书，材料在【我提供的位置】。请先清点资料，判断哪些可直接读、哪些需要提取或 OCR，检查已有工具能否处理，并建立可追溯的来源记录。根据目前材料提出目录和一个样章任务。暂时不要写全文；不清楚的内容列出来，不要编造。把本次进度和下一步写进本书的状态文件。

先用 [提取方法](../methods/text-extraction.md)清点载体及覆盖，再用 [来源登记](../templates/materials/source-register.md)记录原件与处理版。资料较多或持续新增时接 [资料库方法](../methods/source-library.md)。目录、材料缺口和小样任务进入本书 brief/state，示范见 [贯通示例](../examples/getting-started/README.md)。

## 只有想法

> 我想写一本关于【主题】的书，读者大致是【读者】，目前只有【想法或经验】。请按项目中的选题方法，先帮我明确本书要回答的问题、已有依据和需要补的资料；必要时比较几个不同的写作角度，再提出目录草案和小样任务。不要把尚待调研的假设写成事实。

从 [选题方法](../methods/book-planning.md)开始，输出 [本书要求](../templates/book/brief.md)、目录草案和一个 [小样材料包](../templates/materials/unit-pack.md)。需要查证时读 [研究方法](../methods/research.md)：先使用现有搜索能力，必要时提示可增加其他渠道；一路也能开始，不要求补齐固定服务或模型。

## 已有稿件

> 我已有稿件【位置】，这次只希望处理【问题或范围】，必须保留【内容】。请按项目的相应审读或修订流程工作，先说明发现的问题和修改范围，再在已授权范围内另存修订稿，提供具体改动及检查结果。

按加工边界选择 [润色](../workflows/polishing.md)或 [保留原句的缩写](../workflows/abridgement.md)。记录必须保留的信息、引文和表格；修订另存，具体检查见 [修订方法](../methods/revision.md)。仅改一段不必建 Wiki；全书已有初稿时再用 [全书审读](../methods/book-review.md)。

## 每一步怎样接上

AI 依据 [单书模板](../templates/book/)建立目录、brief、AGENTS 和 state，填入已经知道的要求；不为填满模板编造未知。先交一项小任务，分别报告产物、机械检查、内容审读和待确认项。已采纳反馈更新当前要求及下一任务所读文件，不能只留在聊天或私人记忆里。下次读取 state 指定的有效版本继续。

阅读方法和模板不需要 Python。八个核心工具要求 Python 3.9+ 标准库；其余依赖按文件类型和所选路线安装，见 [核心工具](tools.md)与 [可选工具](optional-tools.md)。本项目不替 AI 工具提供账号或联网能力。

## 手动建立本书目录

在仓库根目录运行：

```sh
cp -R templates/book books/my-book
```

打开 `books/my-book/brief.md`，把示例值改成本书要求：读者、要回答的问题、体裁、来源、加工边界、篇幅计数和交付标准。随后在本书的 `AGENTS.md` 中选择流程、补充具体规则，并在 `state.md` 中记录当前采用的指令、稿件和下一步工作。模板放在 `books/名称/` 时，公共文档的相对链接可以直接使用。

按需创建目录：原件进 `raw/`；清洗文本与带编号副本进 `materials/`；单书风格进 `style/`；指令进 `instructions/`；稿件进 `drafts/`；检查进 `reviews/`；交付进 `deliverables/`。不要在原件上注编号。归档旧指令后更新 state，而不是并排保留多个不知谁生效的“最终版”。

任务结束时把文件路径、实际检查、剩余缺口写进 state。机械检查失败则修复对应输入或操作；内容缺证据则补来源或收窄说法。只在触及约定审批点或超出任务授权时提交决定。

`books/` 默认仅跟踪 README，自己的书不进入 Git 提交清单。若打算公开自己的书，需主动调整 `.gitignore`，并检查实际拟提交文件。忽略规则不是公开内容审查。
