# 本书任务

将以下示例值替换为实际要求。不适用写“不适用”，未知写“待确认”并说明是否阻塞当前单元。

| 项目 | 填写方法与示例 |
|---|---|
| 读者 | 写具体处境，例如第一次组织小型活动的人 |
| 目的 | 写读完能做什么，例如能做一份可核对的借用记录 |
| 体裁 | 资料型说明文、采访整理或真实经历；混合体裁注明段落范围 |
| 来源范围 | 原件及版本清单位置；无事实来源时说明采用虚构教学 |
| 加工边界 | 可拆句／只删不改／可补充有来源的解释，分别指向作用范围 |
| 交付格式 | 例如一个 Markdown 单元、来源表和检查记录 |
| 篇幅与计数 | 例如 600—800 基本汉字；是否包括标题、注释；不是含标点字符数 |
| 必须保留 | 具体数字、案例、引文、步骤或人物身份；不要只写“重要内容” |
| 写法要求 | 可靠样本路径或清楚的编辑要求；没有样本不做作者统计 |
| 审批点 | 默认按已授权单元推进；额外结构决定及最终确认由谁负责 |
| 验收 | 机械项目、内容审读范围、最终采用标准及未决项处理 |

版本：初始待填写。填写后记录版本和日期，state 只指向现行版本。
